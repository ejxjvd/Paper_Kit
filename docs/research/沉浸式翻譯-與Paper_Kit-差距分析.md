# 沉浸式翻譯（Immersive Translate）vs Paper_Kit 差距分析

> 對照來源：[[沉浸式翻譯-網頁UI盤點]]（10 頁逐字轉錄）、[[沉浸式翻譯-產品結構與BabelDOC]]、[[沉浸式翻譯-翻譯記錄表格]]、[[pdf2zh.com-線上GUI-盤點]]。
> 定位：Paper_Kit = **本機自用、自帶 API key（BYOK）、零訂閱綁架**（[[paper-kit-ui-goal]]）；沉浸式翻譯 = 線上訂閱制（Pro）。差距分析聚焦「**UI 資訊架構與操作流**」——可免費借鏡的部分，不是複製商業模式。

## 1. 操作流對照（主流程）

| 步驟 | 沉浸式翻譯 | Paper_Kit | 差距 |
|---|---|---|---|
| 進入翻譯 | 左側功能表分類（文字/文件/影片/圖片）→ 文件翻譯頁 | `/` 主頁直入上傳卡 | 差異（Paper_Kit 單一用途，分類無需） |
| 模式切換 | `翻譯單一檔案`／`批量翻譯`（tab） | 無批量概念 | **缺批量模式**（沉浸式翻譯 Pro 限定；Paper_Kit 本機可做單檔串列） |
| 主動作 | 粉紅色大按鈕 `📄 上傳文件並翻譯` | `📂 開始翻譯` primary 按鈕 | 一致（Paper_Kit 已有） |
| 目標語言 | 圖片頁有「將圖片翻譯為：」下拉；文件頁缺（依帳號設定） | /settings 目標語言 | 部分（就地選擇更佳） |
| 支援格式 | PDF/ePub/HTML/JSON/TXT/DOCX/Markdown/字幕 | PDF（＋PPT 視覺、LaTeX 源碼） | 差異（Paper_Kit 深而窄、沉浸式翻譯廣） |

## 2. 資訊架構差距（Paper_Kit 缺，值得借鏡）

### 2.1 版面／結構
1. **模式 tab（單一/批量）**——主頁頂部切換；Paper_Kit 可做「單檔／多檔佇列」
2. **三引擎卡**（Simple Document／PDF Pro／BabelDOC）——引擎選擇產品化呈現（主頁卡片 vs 設定頁下拉）；Paper_Kit 引擎選擇在 /settings 是「簡陋感」主因之一（見 [[Paper_Kit-UI-差距分析]] 批 A）
3. **頂部工具列**：`↪ 回到舊版本`／`📄 使用介紹`／`⏱ 查看翻譯歷史`——Paper_Kit 有 /debug，但**缺「使用介紹」與「翻譯歷史」快捷入口**（歷史＝任務卡片在首頁，無獨立頁）
4. **品牌一致性的導覽**：沉浸式翻譯每頁同框架（nav＋左側欄＋語言）——Paper_Kit 三頁各自獨立（`/`、`/settings`、`/debug` 僅頂部連結），**缺少統一側欄/頁框**

### 2.2 任務歷史（[[沉浸式翻譯-翻譯記錄表格]] vs 票 08）
| 功能 | 沉浸式翻譯 | Paper_Kit |
|---|---|---|
| 表格化（欄位：勾選/文件名/創建時間/頁數/翻譯服務/任務類型/狀態/操作） | ✅ | ❌ 卡片流 |
| 批量刪除／批量下載 mono／批量下載 dual | ✅ | ❌ |
| 分頁（每頁 10 條） | ✅ | ❌ 全量捲動 |
| 每筆顯示所用引擎 | ✅（翻譯服務欄） | ❌ 卡片未顯示引擎 |
| 重試／取消 | ❌ | ✅ 卡片有 ↻ 重試、✕ 取消——**Paper_Kit 勝** |
| 狀態標籤彩色化 | ✅（已逾期=紅） | ✅（轉錄中=藍/完成=綠/失敗=紅，票 11 已做） |

### 2.3 其他
5. **圖片翻譯入口**（上傳/貼圖/拖曳＋目標語言下拉）——Paper_Kit 有 PPT 視覺路徑（票 14）但無「貼圖直翻」入口；紙上功能相同，UI 入口不同
6. **下載頁結構**（多平台 CTA 表格）——Paper_Kit 不需要（本機工具）
7. **通知橫幅**（新模型上線）——Paper_Kit 無此概念（本機無需行銷）

## 3. Paper_Kit 已領先的部分（不必自卑）

1. **BYOK 自帶 key、零訂閱**——沉浸式翻譯 Pro 才有批量/BabelDOC/Zotero；Paper_Kit 全功能免費（只付模型 API 費，NT$0.34/篇實測）
2. **重試/取消/錯誤訊息**——沉浸式翻譯記錄頁只有終結狀態
3. **成本估算**（票 06）——沉浸式翻譯無此概念（訂閱制不需要）
4. **敏感文件紅線**（票 10）＋本機處理——沉浸式翻譯是雲端上傳
5. **LaTeX 源碼路線**（票 15，省 4.7×）——沉浸式翻譯沒有源碼翻譯
6. **深色模式**（票 11）

## 4. 建議納入 Paper_Kit 的改進（合併 [[Paper_Kit-UI-差距分析]] 批計畫）

**批 0（新）：任務歷史表格化**——卡片流 → 表格（勾選/文件名/時間/頁數/引擎/狀態/操作）＋批量刪除＋批量下載＋分頁。工作量中等（現有 JobService 資料齊全，只缺 UI 與批量 API）。
**批 A：主頁就地選項**＋統一側欄/頁框（引擎卡三選、模式 tab）——直接回應「簡陋」。
**批 B：實驗選項**（ignore-cache/threads/custom-prompt/lang-in，旗標已驗證）。
**批 C：URL 輸入＋快捷頁數**。
**每筆任務顯示所用引擎**（小改）。

## 5. 結論

沉浸式翻譯的「完整感」＝**同框架多頁導覽＋表格化歷史＋批量操作＋產品化引擎卡**，功能面 Paper_Kit 核心已齊（甚至勝出）；差距主要在**資訊架構與操作密度**。優先序：批 0（歷史表格）＋批 A（就地選項/頁框）→ 批 B（實驗選項）→ 批 C。
