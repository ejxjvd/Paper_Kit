# 成本比較報告：三引擎實測（#23）

> 2026-08-13 實測。使用者回報：3 種價格差距大、BabelDOC 反而最便宜——「花費金額是最重要問題，
> 應該要詳細比較這 3 種方案的差距」。本報告用**生產環境真實任務數據**（同一份 CH4.pdf、各選 2 頁）
> ＋ babeldoc 同參數實跑復刻，拆解差距來源。

## TL;DR（為什麼 BabelDOC 最便宜）

1. **BabelDOC 不是便宜引擎——它背後掛的就是 DeepSeek**。官方 README 唯一支援的 OpenAI 相容後端
   是 deepseek-chat，單價 = deepseek 引擎 = **輸入 $0.00027/1K**，只有 SiliconFlow（$0.0012/1K）的
   **1/4.4**。BabelDOC 便宜 = DeepSeek 便宜，不是 BabelDOC 技術本身省錢。
2. **三引擎絕對金額都極低**（2 頁約 NT$0.17–0.29），差距是「倍數」不是「金額」。整本 58 頁外推
   約 NT$5–8，仍遠低於付費平台（DeepL 約 NT$470/百頁）。
3. 調查過程順帶定案：BabelDOC 生產記錄 out=0 是 **rich 折行解析 bug**（本日已修復），
   真實 completion ≈ 2830（佔輸入 39%），修正後 BabelDOC 仍是最便宜（同 DeepSeek 單價＋
   較省 token 的版面管線）。

## 單價（USD/1K tokens，cost_service DEFAULT_PRICING 為準）

| 引擎 | 輸入單價 | 輸出單價 | 後端模型 |
|---|---|---|---|
| siliconflow | $0.0012 | $0.0012 | Qwen 系（SiliconFlow 託管） |
| deepseek | $0.00027 | $0.0011 | deepseek-chat |
| babeldoc | $0.00027 | $0.0011 | **deepseek-chat**（README 唯一推薦後端） |

關鍵：輸入單價 siliconflow 是 deepseek 系的 **4.44×**——這是差距的最大單一來源。
輸出單價 siliconflow 貴 1.09 倍，影響較小。

## 生產實測（同 PDF CH4、各選 2 頁、目標 zh-TW）

| 引擎 | 選頁 | tokens in | tokens out | 實測成本 | 台幣（匯率 32） |
|---|---|---|---|---|---|
| siliconflow | 29,30 | 5,682 | 1,751 | US$0.0089 | **NT$0.285** |
| deepseek | 39,40 | 10,688 | 2,999 | US$0.0062 | **NT$0.198** |
| babeldoc | 32,33 | 7,780 | 0（解析 bug） | US$0.0021（低估） | NT$0.067（低估） |
| babeldoc（修正） | 32,33 | 7,780 | ~3,040（39% 外推） | US$0.0055 | **NT$0.174** |

- babeldoc 修正依據：同條件實跑復刻（頁 29,30、同後端）兩次，completion/input 比例
  0.391 / 0.322（差異來自術語抽取開關），取 0.39 外推頁 32,33。
- 頁面不同（29,30 / 39,40 / 32,33）→ 每頁內容量不同，**token 量不可直接互比**；
  單價差異才是可比的（同一頁面、不同引擎的單頁成本差）——見下方同頁復刻。

## 成本分解：差距從哪來

| 比較 | 差距 | 來源 |
|---|---|---|
| BabelDOC vs SiliconFlow | 4.4× 輸入單價 | **單價**（0.00027 vs 0.0012）——主因 |
| BabelDOC vs DeepSeek 引擎 | 同單價，差 token 量 | babeldoc 版面管線 in=7780 vs pdf2zh 10688（頁面不同，僅參考）；BabelDOC 的重排管線對純文字頁較省輸入 |
| DeepSeek vs SiliconFlow | 2.3× 輸入單價 + token 量 | 頁 39,40 內容較多（in 10688），但單價低仍勝出 |

結論：**「BabelDOC 便宜」＝「DeepSeek 便宜」＋（版面管線 token 效率）」**。把 BabelDOC 後端換成
SiliconFlow，它就回到 SiliconFlow 的價格。反過來，DeepSeek 引擎（pdf2zh_next）與 BabelDOC 同價，
只是版面重排品質不同。

## 額外發現（BabelDOC 實跑）

- **DeepSeek cache hit 折扣**：實跑顯示 `Cache hit prompt tokens: 2688 / 1920`——DeepSeek 對
  命中快取的輸入另有折扣價，本專案計價模型用單一輸入單價（保守），實際成本只會更低。
- **術語抽取另計**（auto_extract 開啟時）：babeldoc 實測 `Term extraction: in 1787 / out 1200`——
  約為翻譯主流程的 25% in / 42% out，開關影響可觀。

## 決策建議

1. **金額敏感＋要版面品質** → BabelDOC（DeepSeek 後端）：最便宜的同時版面重排品質最好。
2. **金額敏感＋最簡路徑** → deepseek 引擎（pdf2zh_next）：同單價，直接。
3. **SiliconFlow** 只在需要其生態（免費額度、Qwen 系列模型選擇）時用——2 頁約貴 NT$0.11。
4. 三引擎單頁成本都在 NT$0.08–0.15 等級——**單壓價格的邊際效益很低**，品質與穩定性應同權。

## 附註：順帶修復（本報告調查的直接產物）

babeldoc 生產記錄 out=0 根因：babeldoc 0.6.2 非 TTY 輸出由 rich 以固定寬度折行，
`Completion tokens: 2830` 的數字被拆到次行（source 標記 `main.py:774` 夾中間）→ 原 regex
同行搜不到 → 誤記 out=0。修復（本日，580 tests 全過）：

- **root fix**：CLI runner 統一注入 `COLUMNS=1000`（rich 寬 console，實測三行 token 皆單行）
  ——`cli_adapter_base.py` 共用骨架，pdf2zh_next 一併受益。
- **防禦層**：`parse_output` 前 `_unwrap_rich()`（移除 rich source 標記＋折行殘片併回）——
  任何來源（含手動跑 CLI）的折行輸出都能正確解析。
- 回歸測試：`test_parse_output_unwraps_rich_wrapped_completion`（實跑折行樣本）、
  `test_parse_output_unwraps_wrapped_total_and_prompt`、`test_default_runner_sets_wide_columns_env`。
