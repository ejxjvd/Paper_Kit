# 票 18：歷史批量操作（刪除／下載 zip）

**Parent:** [issue #17 UI 補強規格書](https://github.com/ejxjvd/Paper_Kit/issues/17)

## What to build

歷史頁批量操作：勾選＋全選；「批量刪除」勾選任務（含輸出檔，二次確認 dialog，執行中任務拒絕）；**「批量下載僅譯文（mono）」與「批量下載雙語（dual）」各一鍵**，打包成 zip 回傳。JobService 新增 delete(job_id)，/download-batch 路由伺服端 zip 暫存送完即刪。

**雙語顯示是使用者明定「最不可或缺」的功能**：每筆任務的 dual 下載在重構後必須持續存在（主頁卡片＋歷史表格），批量下載的 mono／dual 兩鍵都要有，缺一不可。

## Acceptance criteria

- [ ] 表格可勾選多筆＋全選
- [ ] 批量刪除彈出二次確認；確認後任務從列表消失且輸出目錄被移除
- [ ] 執行中任務不可被刪除（有提示）
- [ ] 「批量下載僅譯文（mono）」產出 zip，內含勾選任務的 mono 檔
- [ ] 「批量下載雙語（dual）」產出 zip，內含勾選任務的 dual 檔（兩鍵獨立、都要有）
- [ ] zip 送完暫存刪除
- [ ] JobService.delete 單元測試：刪除後 list 不含、輸出目錄消失、執行中拒絕
- [ ] 既有 mono／dual 單筆下載（主頁卡片）維持可用（回歸測試）
- [ ] 現有全部測試綠

**兩軸 code review 裁決（已全數修正）：**

1. **QUEUED 保護缺口（spec 軸，genuinely bypassable）**：原實作只拒 TRANSLATING（「排隊可刪」假設）——但 `start()` 在 QUEUED 就 spawn thread（轉換在 StartTranslation.run 內）。修：QUEUED＋TRANSLATING＋`job_id in self._threads` 都拒，檢查與移除包在 `self._lock`。
2. **zip 暫存檔名碰撞（兩軸都抓）**：固定名 `paper-kit-{kind}-{len}files.zip` 並行下載互相覆寫＋unlink 誤刪 → uuid 前綴。
3. **kind 未驗證（standards）**：`kind == "mono" else dual` typo 靜默走 dual → route 驗證，未知 kind 400。
4. **缺批量重試／取消（spec 軸）**：票 17 裁決移除的單列重試/取消需有替代（issue #21 補記）→ 批量工具列加「↻ 批量重試」「✕ 批量取消」兩鍵（module-level `_batch_retry`/`_batch_cancel`，can_retry/can_cancel 過濾後 loop）。
5. **巢狀 handler（standards：Duplicated Code + 不可測）**：`_delete_jobs`/`_batch_retry`/`_batch_cancel` 抽 module-level（回傳計數）；`_history_rows` 收攏 initial 與 refresh 的 rows 建構。
