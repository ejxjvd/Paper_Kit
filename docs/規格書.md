# Paper_Kit 規格書（Spec / PRD）

> 源起：[[2026-08-12-Paper_Kit-計畫]]（研究定稿）＋ 2026-08-12 使用者定調（自建 UI 翻譯器、免除線上工具綁架）。本規格書為開發藍圖；GitHub repo 已開 issue 同步。術語用語見 [[2026-08-12-Paper_Kit-名詞術語解釋]]。

## Problem Statement

使用者讀外文論文／簡報需要翻譯，但現有方案各有問題：

- **線上工具綁架**：BabelDOC 訂閱（Pro NT$299/月、Max NT$899/月）有配額與漲價風險；沉浸式翻譯會員同樣受制於廠商政策——「工具是借來的，隨時可能被拿走或漲價」。
- **貴**：DeepL API 約 NT$470/本；翻譯社 NT$1,000–3,000+/份。
- **不自由**：線上工具引擎固定（不能自選模型）、參數不可控、術語表格式受限。
- **硬體限制**：桌機 GPU 故障（2026-08-11 起），本機模型不可行——只能走雲端 API（DeepSeek flash ＋ SiliconFlow）。

最終目的（使用者明示，2026-08-12）：**建立一個有 UI 介面的翻譯器，免除被線上工具綁架**——工具要握在自己手上。

## Solution

本機 Web 應用（**NiceGUI，純 Python 一體**）：

- 拖放 PDF → 選引擎／頁面範圍／術語表 → 一鍵翻譯 → 產出 **mono（單語）＋ dual（左右並排雙語）** PDF，瀏覽器內預覽。
- **Ports & Adapters**：所有引擎（pdf2zh-next、BabelDOC 線上、免費引擎）藏在 `TranslationEnginePort` 介面後——**換引擎＝換插頭，UI 與業務邏輯零改動**（免除綁架的架構保證）。
- 任務狀態機＋歷史紀錄＋**成本估算**（翻之前先估價，翻之後記實際用量）。
- 術語表 CSV 匯入＋**自動術語提取**（-next 原生 `--term-*`，Kimi 角色免復刻）。
- 開發方法：**TDD（紅→綠）＋ 務實 DDD**（分層、Ports & Adapters、Ubiquitous Language；不做 Event Sourcing／CQRS）。

## User Stories

1. 作為使用者，我想要拖放上傳 PDF 並翻譯成繁體中文，以便閱讀外文論文。
2. 作為使用者，我想要**公式原樣保留**（向量字符、可複製縮放），以便譯文在技術上不失真。
3. 作為使用者，我想要一次拿到 mono 與 dual（左右並排）兩種輸出，以便需要時比對原文。
4. 作為使用者，我想要指定**頁面範圍**（如 1-2 頁）翻譯，以便只為需要的部分付費。
5. 作為使用者，我想要匯入**術語表（CSV）**，以便全文專有名詞翻譯一致。
5b. 作為使用者，我想要**擁有多份術語表**（不同領域／語言對各自成檔），以便一套工具應付不同論文。
5c. 作為使用者，我想要翻譯前**挑選要套用哪幾份術語表**（可複選組合），以便每篇論文用適合的術語。
6. 作為使用者，我想要**自動術語提取**（引擎先掃全文抽術語），以便不用手建術語表。
7. 作為使用者，我想要**自由選擇翻譯引擎**（SiliconFlow gemma／DeepSeek／免費引擎／BabelDOC 線上），以便在成本與品質間取捨。
8. 作為使用者，我想要看到**每個任務的進度**（排隊→翻譯中→完成／失敗），以便知道要等多久。
9. 作為使用者，我想要翻譯前看到**成本估算**、完成後看到**實際 token 用量與花費**，以便控制開銷。
10. 作為使用者，我想要**歷史紀錄**與重下載結果，以便之後再取用。
11. 作為使用者，我想要**取消／重試**失敗的任務，以便不需重新上傳。
12. 作為使用者，我想要在 **UI 內設定 API keys**（不必碰環境變數），以便安裝即用。
13. 作為使用者，我想要**漂亮的、可大量美化的介面**（主題、配色、排版），以便用得愉悅。
14. 作為使用者，我想要**流暢的互動**（事件驅動、不整頁重載），以便操作順手。
15. 作為使用者，我想要**清楚的錯誤訊息與可追蹤的 log**，以便故障時好除錯（DEBUG 方便好找）。
16. 作為使用者，我想要只用**自己帶的 API key／免費引擎**也能完整運作，以便不被任何訂閱綁架。
17. 作為使用者，我想要在**瀏覽器內預覽**翻譯結果，以便不需額外軟體。
18. 作為使用者，我想要**指定輸出位置**，以便檔案落在我要的地方。
19. 作為使用者，我想要**預設設定**（預設引擎、目標語言、輸出目錄），以便日常翻譯一鍵完成。
20. 作為使用者，我想要翻譯**表格文字**（可選開啟），以便表格密集論文也能讀。
21. 作為使用者，我想要**敏感文件保護**（上傳即提示「文件會送雲端」；R18／機密走本地模式或拒絕），以便堅守既有紅線。
22. 作為使用者，我想要**掃描件 OCR 翻譯**（Phase 2），以便沒有文字層的 PDF 也能處理。
23. 作為使用者，我想要**PPT 視覺翻譯**（Phase 2，gemma 眼睛逐頁），以便簡報設計版面保留。
24. 作為使用者，我想要**LaTeX 源碼翻譯**（Phase 2，翻 .tex → xelatex），以便有源碼的論文 100% 保真。
25. 作為使用者，我想要**成本上限警告**（估算超過可設門檻時先確認），以便不怕不小心燒錢。

## Implementation Decisions

- **技術棧**：Python 3.12+；**NiceGUI**（底層 FastAPI＋WebSocket，事件驅動）；uv 管理依賴；SQLite 持久化。
- **分層（務實 DDD）**：
  - `domain`：TranslationJob（聚合根＋狀態機）、Glossary／LanguagePair／PageRange（值物件）、CostCalculator（領域服務，純規則無 IO）
  - `application`：指令處理器（StartTranslation／CancelJob／RetryJob…）、成本估算服務
  - `infrastructure`：引擎 adapter（CLI 包裝）、SQLite repository、log 設定
  - `presentation`：NiceGUI 頁面（薄層，只呼叫 application commands）
- **Ports & Adapters 契約**：`TranslationEnginePort.translate(job) → job_result`；adapter 以 subprocess 呼叫 `pdf2zh_next` CLI（參數由 adapter 內部對應，UI 不知情）。已知 adapter：
  - `Pdf2zhNextAdapter`：`--siliconflow --siliconflow-model google/gemma-4-31B-it --glossaries <csv> --pages <range> --only-include-translated-page` 等
  - `BabelDocAdapter`（Phase 2，線上 API）
  - `FreeEngineAdapter`（SiliconFlowFree／Google／Bing，零成本備援）
- **POC 教訓（2026-08-12 實測）**：
  - SiliconFlow 帳號在**國際站**：base-url 必須 `https://api.siliconflow.com/v1`（-next 預設 `.cn` 會 401）→ adapter 內預設正確並可設定
  - -next **不吃 process env**，key／base-url 一律經 CLI 旗標傳 → adapter 設定物件直接對應旗標
  - **上游暫時性故障**：實測遇 `50507 Request failed: Unknown error`（500）＋ translate 階段連線 ESTAB 但 hang 8 分鐘 → adapter 必須包 **retry（2-3 次退避）＋ request 逾時（>5 分鐘視為失敗）**，並把階段進度回報 UI（否則卡死無感）
- **術語表格式**（POC 實測定案）：CSV **含標頭列** `source,target[,tgt_lng]`（tgt_lng 選填，寫了必須與目標語言相符否則整列跳過）；預設目標語言 `zh`（CLI 無語言旗標，lang_out 只能由 Python API/設定改）→ adapter 用 Python API 傳 `lang_out="zh-TW"` 以確保繁體輸出；多檔可逗號分隔；自動提取走 `--term-siliconflow`（Kimi 角色原生版）。
- **術語庫＝多份管理＋翻譯時挑選**（2026-08-12 使用者新增需求）：術語表是**庫**——多份各自命名（領域／語言對），UI 提供管理（匯入／刪除／改名）；**每次翻譯前在設定頁 multi-select 挑選套用哪些**（預設全選），選擇隨任務記錄；engine adapter 把選中的組合以逗號分隔帶入 `--glossaries`（POC 已驗證引擎支援多檔）。
- **任務狀態機**（domain 核心，prototype 定案）：
  ```
  queued → translating → completed
                    ↘ failed →（可 retry 回 queued）
                    ↘ cancelled（使用者取消）
  ```
- **成本模型**：CostCalculator 以官方每頁 token 統計（4,703–7,382 tokens/頁）＋引擎單價參數化（DeepSeek 漲價公告 2026-08-06 → 單價為設定而非寫死）；完成後以引擎回報的實際 token usage 更新紀錄。
- **UI**：Quasar 元件＋自訂 CSS 主題（大量美化）；深色模式；任務卡片（狀態徽章＋進度條＋成本）。
- **敏感紅線**：上傳時偵測並提示（繼承 [[Translation_Kit]] 紅線；R18 不走 SiliconFlow 雲端）。
- **Phase 2**：掃描件 OCR（RapidOCR 選項）、PPT 視覺路徑（gemma 眼睛）、LaTeX 源碼路線、BabelDOC 線上 adapter。

## Testing Decisions

- **接縫（2026-08-12 與使用者確認）**：3 處——
  1. **`TranslationEnginePort`（主接縫）**：application 測試以 FakeEngine 注入，驗證「任務被正確送出、結果被正確存回、失敗可重試」；不碰真實引擎
  2. **domain 純單元**：TranslationJob 狀態機合法／非法轉換表、Glossary 比對規則、CostCalculator 邊界值——無 IO 純函式
  3. **adapter 整合 smoke（唯一標 slow）**：fixture 2 頁 PDF 對真實 pdf2zh-next，斷言 mono／dual 產出（每版引擎升級跑一次）
  - UI 不測 widget；UI 薄層呼叫 application commands，application 即 UI 的接縫。
- **好測試定義**：只測外部行為、不測實作細節；期望值來自獨立來源（狀態機轉換表、已知 fixture 的斷言）——重構後測試不該壞。
- **先例**：[[Translation_Kit]] TDD 文化（paste-vision TDD PASS=15、frontmatter-validator TDD）；流程 = 紅→綠循環、一次一個垂直切片。

## Out of Scope

- Event Sourcing／CQRS／全套 Repository＋ORM
- 多使用者認證、雲端部署、行動端 app
- 掃描件 OCR、PPT 視覺、LaTeX 路線、BabelDOC 線上 adapter（Phase 2）
- 本機模型推理（桌機 GPU 故障期間；Ollama 引擎列為「未來可選」）
- 論文以外的進階排版（雜誌級 typography）
