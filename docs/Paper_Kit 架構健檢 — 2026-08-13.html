1 · 引擎挑選區加深：EnginePickerSection 元件

Strong in-process

presentation/app.py:1496-2082（_index_page）· tests/presentation/test_index_page.py · test_sensitive_output_ui.py

Before — interface 與 implementation 等寬

After — 一個 deep module

Problem

付費區與免費 LLM 區單卡化做了兩次：_render_paid_key_card 與 _render_free_key_card 逐行複製；三份「目前引擎」可變狀態必須人工同步——_on_sensitive_change 只同步付費單卡，不動 free-key 下拉。deletion test：抽元件是「集中」約 120 行重複，不是搬家。

  • interface 縮小：主頁只問 can_select，不推導規則
  • 測試打在一個介面上：1616 行的端到端模擬縮回元件測試

3 · 定價收進 EngineSpec（修「付費引擎被估成免費」bug）

Strong ports & adapters

cost_service.py:21-30（DEFAULT_PRICING 僅 8 支）· engine_registry.py（18 支）· app.py:317-321（_notify_estimate）

Before — 雙 registry 平行演化失同步

After — 定價與引擎同處

Problem

現存 correctness bug：新增 10 支引擎（含付費 openai／gemini-pro）沒進 DEFAULT_PRICING，pricing_for 落 fallback → 付費引擎顯示「免費引擎無費用」；加引擎＝改兩處且無測試守衛。

  • 消除錯誤估價（使用者信任議題）
  • locality：定價與引擎規格同處，加引擎改一處
  • 風險低：行為不變，純資料收斂＋測試補 10 支引擎

6 · 設定頁 bind_value 顯式化＋cache 開關單一真相

Worth exploring in-process

8 · 測試介面誠實化：私有函式不再被 production 綁架

Worth exploring mock

tests/presentation/test_index_page.py（1616 行 > _index_page 590 行）· pdf2zh_next_adapter.py:110-112（re-export _kill_tree）· handlers.py 私有名被公開 import

Before — `_` 只是裝飾

test_delete_dialog monkeypatch _refresh

← production 形狀被測試 import 路徑綁架

After — 規則提純函式、UI 只留綁定

UI closure 只做綁定
測試縮回純函式層

Problem

presentation 測試的介面就是 app.py 的私有函式（_index_page／_render_card 被直接 import）；規則全在 closure 內，小行為只能靠 1616 行端到端模擬測到（locality 差）。

Solution

把 _pick_engine／_card_disabled／_has_key 規則提為 handlers 純函式（延伸既有 P2 收斂模式），UI 只留綁定。

  • 測試表面縮小：純函式直接測、UI 測綁定
  • 與候選 1、2 連動（同一批規則）

Top recommendation

先做 候選 3（定價收進 EngineSpec）——它是現存 correctness bug（付費引擎估成免費），改動小、零行為變化、純資料收斂＋補測試，先把錯誤數字從使用者眼前拿掉。

然後把 候選 1＋2＋8 合併成一次「引擎挑選區加深」：EnginePickerSection 元件＋規則模組＋純函式化，一次處理最大熱點（590 行 closure 堆）與測試表面，同一區的改動只重構一次。
