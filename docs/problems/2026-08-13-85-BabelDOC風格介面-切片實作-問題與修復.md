## 問題 1：NiceGUI `user.find()` 找不到隱藏元素——不是回空集，是 raise

**現象**：測試「babeldoc 進階面板預設隱藏」用
`user.find(kind=ui.column, marker="babeldoc-advanced")` →
`AssertionError: expected to find at least one...`。

**根因**：NiceGUI testing 的 `find()` 預設 `only_visible=True`——隱藏元素不匹配
且**會 raise**，不是回空集合。測試把「找不到」誤當成回空集處理。

**解法**：隱藏斷言＝`with pytest.raises(AssertionError): user.find(content="BabelDOC 進階選項")`；
顯示斷言＝`.visible is True`（`set_visibility` 對應 `element.visible` property）。

**立規**：NiceGUI UI 測試——斷言元素存在＝`find()` 正常回傳；斷言元素隱藏＝
`pytest.raises(AssertionError)` 包 `find()`；**不要假設 find 回空集**。

## 問題 2：asyncio 包裝把 StopIteration 藏成 RuntimeError

**現象**：flow 測試報 `RuntimeError: coroutine raised StopIteration`，traceback
找不到真凶。

**根因**：測試代碼 `next(c for c in … if label in …)` 在空 generator 上 raise
StopIteration；asyncio 把它包成 RuntimeError。真正的錯是測試 label
「移除段落非公式線條」與 UI label「移除段落**中的**非公式線條」字串不符。

**解法**：測試匹配字串改用穩定片段（「非公式線條」）。

**立規**：UI 測試匹配 UI 文字用穩定片段（「的」等虛詞會造成前後文差異）；
看到 `coroutine raised StopIteration` 先查可迭代來源是否為空（label 錯配最常見）。

## 問題 3：終態任務不能構造 FAILED——狀態機合法路徑

**現象**：構造 FAILED 任務先 `COMPLETED→QUEUED` 再 `COMPLETED→TRANSLATING` →
`InvalidTransition`。

**根因**：COMPLETED 是終態（領域狀態機），不可回退。

**解法**：FAILED 任務構造＝QUEUED→TRANSLATING→FAILED（與引擎真實失敗路徑一致）。

## 問題 4：`_refresh` 簽名擴充後 monkeypatch 測試掛

**現象**：`test_delete_dialog_survives_refresh` 報
"got an unexpected keyword argument 'quota_label'"。

**解法**：monkeypatch 版 `_no_clear_refresh` 簽名加 `**kwargs`：
`(cards, svc, cost_svc, settings_svc, memo, *extra, **kwargs)`。

**立規**：monkeypatch 取代具名參數漸增的函式時，替身簽名一律含 `*extra, **kwargs`
（此類測試已發生 2 次：`engine_labels` 與 `quota_label`）。

## 問題 5：除錯 DB 被 `git add -A` 誤入 commit

**現象**：`run_tmp_debug.py` 建立的 `tmp_debug_dir/pk.db`（SqliteJobRepository DB）
被提交進 `35a2277`；rmdir 失敗殘留。

**解法**：`rm -rf tmp_debug_dir`＋`git rm --cached`＋新 commit `0719a23`
（已 push 無法 amend）。

**立規**：除錯產物一律含 `tmp_` 前綴；commit 前 `git status` 目視新增檔案。
