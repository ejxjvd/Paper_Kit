# 票 27 實作問題與修復（LaTeX 整合主 UI）

> 2026-08-13。票 27（GitHub issue #32）：LaTeX 源碼路線整合主 UI＋.tex 預設走 LaTeX。
> 實作中遇到的問題與解答——依紀律 5 總結存放。

## 問題 1：NiceGUI user_simulation 測試順序污染（spy 靜默失效）

**現象**：新增測試 `test_tex_upload_auto_selects_latex_engine`（上傳 .tex → 自動鎖 latex → 任務記
latex，側信道 spy `build_engine` 驗證 key fallback）——單獨跑 **1 passed**；與它前面的
`test_engine_cards_include_latex_card`（只開頁＋找卡，無 monkeypatch）一起跑就 **FAILED**：
`assert seen.get("eid") == "latex"` 失敗（spy 沒被呼叫），但 `job.engine_id == "latex"` 卻通過
（任務真的建立了）。方向性實驗：cards→tex 敗、tex→cards 過——**順序相依，非功能 bug**。

**調查**：spy 沒被呼叫但任務建立＝`build_engine` 走的路徑沒經過 monkeypatch 的 app 名稱空間？
單獨跑證明 monkeypatch 有效；兩測試間唯一差別是前一個 user_simulation 的存續。嘗試外部 debug
腳本（stdin python）失敗——NiceGUI `ui.run` 需要真實 script 檔（script-mode 檢查）。

**解答**：不追 user_simulation 的 Client 殘留細節（已知類別問題：先前 #85 有「測試隔離
Client.instances 殘留」教訓）——**把順序污染敏感的斷言從 UI 測試拆出去**：

1. UI 測試只保留「結果語意」斷言（`job.engine_id == "latex"`、卡片高亮、守衛 notify）——
   build_engine 注入 `FileWritingFakeEngine`（不打真 API），不 spy。
2. key fallback 語意拆成**純函式測試**：直接呼叫 `_resolve_task_engine(settings, "latex")`
   ＋monkeypatch spy（無 user_simulation 參與，零污染）——驗證「latex 未填 key 沿用 deepseek
   槽位」與「兩者都無 key 拋 EngineError」。

**教訓**：
- NiceGUI UI 測試彼此有順序污染風險（前一測試的 Client/背景任務殘留）——**測試內的 spy
  斷言最脆弱**（依賴 monkeypatch 在 UI 事件鏈的穿透），核心行為一律走側信道（job 狀態）；
  複雜語義（key fallback 等）拆純函式測試，不混進 UI 測試。
- 組合測試（`A→B` vs `B→A`）是最快的污染定位法。

## 問題 2：Git Bash heredoc 反斜線雙重轉義（SyntaxWarning）

**現象**：測試檔內 `b"\documentclass{article}..."` 出現 `SyntaxWarning: invalid escape
sequence '\d'`——bytes literal 內的反斜線被吃掉一層（JSON 參數層→bash 層→檔），LaTeX
內容變成 `\d` 開頭（pypdf 還因此把 .tex 當 PDF 讀：`invalid pdf header: b'\\docu'`）。

**解答**：bytes/str 內含反斜線一律用 raw：`rb"\documentclass{article}"`——raw bytes
不再解析 escape，內容原樣。

**教訓**：從工具參數寫測試 fixture 內容時，反斜線會經 JSON→shell→檔案 三層轉義——
用 raw literal 一次斷根（同時避免誤判：.tex 內容被 pypdf 讀到會印 warning，干擾判讀）。

## 問題 3：EngineError import 路徑（小）

**現象**：測試寫 `from paper_kit.domain.errors import EngineError` → ModuleNotFoundError。

**解答**：`EngineError` 定義在 `paper_kit/application/ports.py:14`（不是 domain/errors）。

## 附：設計決策（本票）

- **latex 的 API key 語意**：後端＝deepseek-chat（README 唯一推薦後端）→ key 未獨立填時
  沿用 deepseek 槽位（`_resolve_task_engine` 特判）；設定頁 latex 卡（ENGINE_CARDS 迴圈
  自動出現）可覆寫獨立 key。兩者皆空 → 友善錯誤（不 build_engine）。
- **latex＋PDF 守衛**：`_start_job` 前置擋下（notify「僅適用 .tex」＋不建任務）——不悄悄
  fallback 別支引擎（#83 靜默誤動作教訓）。
- **.tex 無頁數語意**：暫存時不讀 pypdf（page_select 清空＋label「整份編譯（無頁面範圍）」）；
  任務 total_pages/pdf_pages=None（進度框不顯示頁數）——「N/M 頁」只屬於 PDF。
- **估價**：`estimate_for_pdf` 對 .tex 天然 None（pypdf 解析失敗 → except → None，UI 靜默
  跳過）；完成後用實際 tokens × latex 單價（deepseek-chat 同價）顯示。
